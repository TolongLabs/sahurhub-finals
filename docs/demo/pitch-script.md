# SahurHub — Finals Pitch Script (QBH Physical Final, 25 Jul 2026)

> **Format:** 3-minute pitch + 1-minute judge Q&A (finals agenda). **Budget: 0:55 slides speedrun · 1:45 live demo · close by 2:40.**
> **Penalty:** **−10 marks per 5 seconds** past 3:00 — the script targets **2:40 spoken-done**, never 3:00.
> **Deck:** [`pitch-deck.html`](pitch-deck.html) — **5 slides** (PDF export: [`pitch-deck.pdf`](pitch-deck.pdf)). Arrow keys / click to advance; no preview panel.
> **Demo mode:** **LIVE** on the SahurHub device (freshly rebuilt on-site) + phone remote at `https://<pi-ip>:8443/phone`. Bluetooth speaker for room volume; **USB speaker packed as fallback**.
> **Speakers** (assign at rehearsal): **SPEAKER A** (pitch voice) · **DEMO-DRIVER** (holds device + phone, drives everything).
> **Convention:** plain text = **spoken** · _italics_ = on-stage action · `NOTE:` = internal, never spoken.
> **Do not hard-commit Sahur's exact replies.** The persona is non-deterministic — react to what it actually says; the task facts it captures are the reliable part.

# PART 2 — THE LIVE DEMO (0:55–2:40) · DEMO-DRIVER

> ## ⚠ Presenter safety (read once, keep to the side)
>
> - **Seed duration:** the demo task MUST be "**in one minute**" — that schedules the escalation inside the demo. Never say "in five minutes" on stage.
> - **Volume:** Bluetooth speaker paired before the session; if audio stutters or desyncs lip-sync, the USB speaker is plugged in as fallback — switching is one audio-sink change, rehearsed.
> - **Phone stays in DEMO-DRIVER's hands.** Show it; don't pass it. One audience/judge exchange max, and only if time allows at 2:05.
> - **Barge-in:** speaking while Sahur talks cuts it off (abort-signal barge-in). Use it deliberately if a reply runs long — talking over it is in character for us, dead air is not.
> - **If Wi-Fi/hotspot drops mid-demo:** the kiosk character stays alive on-screen. Narrate over it, show the phone UI locally, and pivot to the close line early. Do not debug on stage.

## 2.1 Device reveal + seed the task (0:55–1:10)

_Hold the device up, screen out. Sahur idling, ONLINE badge visible._

> "This is Sahur. He's listening through my phone."

_Push-to-talk on the phone remote, spoken clearly into the mic:_

> "Sahur — I need to drink some water **in one minute**."

_Sahur replies in character; his reply speaks the captured task + duration back. Let it land — the room hears the voice for the first time. React, don't talk over this one._

## 2.2 Task-list flash (1:10–1:25)

_Hold the phone up beside the device, task list visible._

> "I never said 'add task' — it just heard me. There it is, counting down."

## 2.3 Keep talking → THE KNOCK (1:25–2:05)

_Lower the phone. Talk to the audience, deliberately ignoring the device._

> "And the engine under the bit is dead reliable — the facts never bend. Which means right now, a timer is counting down to—"

_**THE KNOCK.** Sahur interrupts with the escalating reminder — knock animation + spoken menace. Stop mid-sentence. Look at the device. Let the room laugh. LIFT THE DEVICE toward the judges so they see the knock animation up close._

> "…he means me. And it only gets worse — gentle, direct, unhinged."

`NOTE:` If the knock hasn't fired yet, vamp one more beat — it fires at seed+60s, it WILL come. Never fill the gap with a second feature.

## 2.4 Obey → cleared + bonus poke (2:05–2:25)

_Drink water (or mime it), then into the phone:_

> "Okay, done — I drank it."

_Sahur acknowledges; task clears on the phone. If pacing is ahead of schedule, one bonus beat — tap poke on the remote:_

> "When we miss him, we poke him. He hates it."

`NOTE:` The poke beat is the FIRST thing cut if running behind. Check the clock at 2:05: behind → skip straight to 2.5.

## 2.5 Close (2:25–2:40) · SPEAKER A

_A steps forward; DEMO-DRIVER holds the device up between you._

> "SahurHub. Works perfectly. Behaves terribly. Built on this table, this afternoon. It knocks until you obey. Terima kasih."

`NOTE:` Land "Terima kasih" by **2:40**. Everything after is buffer, not content.

# PART 3 — JUDGE Q&A (1:00) · both

_Deck parked on Slide 5. First sentence answers the question; detail only if asked. ~20s per answer max._

**Routing:** premise/creativity → SPEAKER A · tech/Qwen/build → DEMO-DRIVER.

**"Why is this useless? It sounds like a real task reminder."**

> "The engine is a perfectly reliable straight man — the character is completely unhinged about it. Nobody asked for a reminder that percussively menaces you on schedule. The uselessness is the delivery, committed to without irony."

**"What does Qwen actually do here?"**

> "Three models chained on every turn: qwen3-asr-flash transcribes, qwen3.6-flash writes the reply and silently extracts the task in the same call, qwen3-tts-flash speaks it. Photos go through qwen3-vl-flash. There is no product without Qwen — it's the entire brain."

**"You built this in two hours?"**

> "Yes — here's the repo, created at 12:4X today, commit by commit. We spent the week engineering it to be rebuildable inside the window; that constraint shaped every technical choice."

**"Why hardware? A web app would've been easier."**

> "A browser tab can be closed. A wooden log on your desk that knocks at you cannot be ignored — the menace is the product, and menace needs a body."

**"What happens if I talk to it right now?"**

> _(DEMO-DRIVER, into phone, invite it — audience chaos is safe: the persona is SFW-gated.)_ "Ask him yourself."
